## 1. 项目概述

「互补数字人」是一款微信小程序，核心理念是 **"遇见另一个视角的你"**：用户先完成 MBTI / 大五人格测评，系统基于自研算法生成与其人格 **互补** 的 AI 伙伴，之后通过与 AI 伙伴的多轮对话获得差异化视角、具体行动建议与结构化追问。

- 技术栈：uni-app（Vue 3 + TypeScript）+ 微信小程序，前后端分离的轻量架构
- 数据存储：全部本地（微信存储 / H5 localStorage 双兜底），无自建后端数据库
- AI 接入：OpenAI 兼容接口直连（多模型失败转移）+ 可选 uniCloud 云函数网关（服务端持密钥）
- 测试：vitest，9 个测试文件、128 个用例，覆盖核心算法与流式解析

**产品流程**

```
首页（测评引导）→ MBTI 测评（16 题）→ 大五测评（30 题，可选）
→ 创建互补人格（自研互补算法生成 complementMbti / complementBigFive）
→ 对话（流式输出 + 结构化回复 + 记忆衰减 + 反馈学习）
→ 设置（模型管理 / 数据备份 / 数据清理）
```

## 3. 核心架构与数据流

### 3.1 全局状态：自制单例 reactive store

所有页面共享同一个 store 实例（[stores/persona/index.ts](file:///workspace/complement-digital-human-mp/src/stores/persona/index.ts)）。

```ts
// 惰性单例：首次调用时创建，后续复用
let storeInstance: ReturnType<typeof createStore> | null = null
export function usePersonaStore() {
  if (!storeInstance) storeInstance = createStore()
  return storeInstance
}
```

- `createStore()` 内部使用 `ref` + `computed`，最终 `return reactive({...})` 暴露扁平状态与方法。
- 状态清单：`userMbti`、`mbtiProfile`、`bigFiveProfile`、`personas[]`、`activePersonaId`、两套测评进度与答案、两个完成标记。
- **持久化**：任何修改通过 `saveToStorage()` 写入 `STORAGE_KEYS.personaData`；启动时 `loadFromStorage()` 反序列化并 `normalizePersona()` 补齐缺省字段（重要：保证老数据可读）。
- 关键上限常量：`MAX_PERSONA_COUNT=5`、`MAX_USER_FACTS=12`、`MAX_MEMORY_FACTS=50`、`MAX_IMPORTANCE=5`、`MAX_GROWTH_LEVEL=10`、`CONVERSATIONS_PER_LEVEL=10`、`COMPLEMENT_COOLDOWN_DAYS=7`。

> ⚠️ 兼容性：`canModifyComplement()` 与 `getRemainDays()` 内置 **旧 30 天冷却 → 新 7 天冷却** 的自动迁移逻辑（对存量 `nextModifyTime` 减去 `30天 - 7天` 处理）。

### 3.2 AI 对话数据流（★ 重点）

一次完整对话请求的处理链（[api.ts](file:///workspace/complement-digital-human-mp/src/pages/chat-conversation/modules/api.ts)）：

```
用户发送消息
  → sendMessage()（index.vue）
     → callDeepSeekAPI({ userMessage, ctx, history, onText })
        → 构建 system = buildSystemPrompt(ctx) + buildStructuredInstruction()
        → usableModels(readModels())   # 过滤启用/有Key/有地址，快速模型优先
        → 逐个 directRequest（直连，流式）—— 失败/格式异常自动切下一个
        → gatewayRequest（网关兜底一次，需开启 use_cloud_proxy 且有网关地址）
        → 全失败则 throw
  → 收到 ChatResponse { text, structured, memoryUpdates }
     → 页面渲染结构化气泡（perspective + 建议列表 + 追问 + 反馈按钮）
     → 记忆层：应用 AI 抽取的 memoryUpdates（facts / summary / behavior）
       —— 缺失或为空时回退旧规则（正则抽取用户事实 / 截取摘要 / inferBehaviorFromMessage）
```

**失败转移（failover）判定**：直连或网关返回后，`parseStructuredReply(content)` 若发生解析降级（`structured.perspective === content`，即 `isFormatFailure`），视为该模型不可用，返回 `null` 触发下一个模型。因此**只要配置了多个模型，单个模型不流畅或格式不稳时会自动切换**。

### 3.3 流式输出实现

- 底层：`uni.request({ enableChunked: true })` + `task.onChunkReceived(...)`（仅微信小程序支持，H5 回退非流式）。
- `ApiDeps` 抽象层（[api.ts](file:///workspace/complement-digital-human-mp/src/pages/chat-conversation/modules/api.ts#L40-L44)）：
  - `request(options, onChunk)` —— 测试可注入 mock；
  - `supportsChunked?: boolean` —— 当前环境是否支持分块（测试环境置 false）。
- `createSseAccumulator(onText)`：跨 chunk 缓冲半行，按 `\n` 切行，`parseSseLine` 解析 `data: {choices:[{delta:{content}}]}`，跳过 `[DONE]`；结束时 `flush()` 返回累积完整纯文本（用于结构化解析）。
- 流式渲染（index.vue）：消息以 `streaming: true` 入队 → `onText` 增量累加 → `scrubStreamText()` 把"未收全的 JSON"清洗成可读文本（完整 JSON 取 `perspective`，未完整时剥掉骨架保留内容）→ 请求完成后替换为 `formatStructuredText()` 结果。
- 慢响应提示：`startSlowTimer()` 8 秒无内容则显示"模型思考中"提示条，收到首个增量文本即消失。
- 失败重试：`pendingRetry = { text, history }` 缓存最近一次请求；失败消息带 `retry: true`，点击"↻ 重试"删除错误气泡并原样重发。

## 4. 核心算法

### 4.1 MBTI 测评（16 题）

- 题目 `mbtiQuestions`：4 个维度各 4 题，ID 不连续（1,5,9,13 / 2,6,10,14 / ...），`dimension` 字段为 `'EI'` 等，选项 `0` 取字母 `[0]`，选项 `1` 取 `[1]`。
- 计分：每维 `counts[字母]` 统计 → `scores = ratio(a, b) = round(a/(a+b)*100)` → `type` 取每维 >50 的字母。
- 置信度 `computeConfidence`：各维 `|score - 50| * 2` 均值（越极端越自信）。

### 4.2 大五测评（30 题，IPIP 风格）

- 5 维度 `O/C/E/A/N` × 6 题 = 30 题，每维含正向与反向题（`reversed`）。
- **非对称选项映射**：`bigFiveOptionScores = [8, 32, 50, 68, 92]` —— 刻意弱化"一般"选项，鼓励表达倾向，避免分数向 50 塌缩。
- 权重：部分题目带 `weight`（0.9 / 1.1），加权平均。
- **置信度 = 强度 × 一致性**：
  - 强度 = 各维 `|score-50|*2` 均值；
  - 一致性 = 正题得分与反题反转得分的接近程度（仅单侧题目时保守取 0.5，避免置信度虚高）。

### 4.3 互补人格生成（[algo.ts](file:///workspace/complement-digital-human-mp/src/stores/persona/algo.ts)）

原则：**"互补但可理解"** —— 不是无条件取反，而是按互补度决定翻转数量，且优先翻转用户倾向最弱的维度。

- `calculateComplementMbti(mbti, level, scores)`：
  - `flipCount = round(level/100 * 4)` 决定翻转几个维度；
  - 按 `|score-50|` 从弱到强排序，翻转最弱的 `flipCount` 个字母。
- `calculateComplementBigFive(scores, level, mbtiContext, confidence)`：
  - 幅度 `magnitude = ratio * (0.4 + 0.6 * trust)`，置信度低时削弱偏移；
  - 边界收缩：镜像点向 50 拉近 ×0.75，互补落在 20~80 可对话区间；
  - **N（情绪稳定性）特殊处理**：互补只向"情绪稳定"方向移动，永不制造高焦虑；
  - **MBTI ↔ 大五一致性约束**：被 MBTI 翻转的维度，大五互补方向必须一致（`mbtiFlipRule` 映射）。
- `inferBehaviorFromMessage`：正则从用户消息推断 `emotionTendency / decisionStyle / expressionStyle / deepNeed`。
- `adjustBigFiveWithBehavior`：**贝叶斯式融合**，用对话行为画像以 0.2 权重微调静态大五测评分，形成"活的"人格输入（prompt 中体现）。

### 4.4 记忆系统（[memory.ts](file:///workspace/complement-digital-human-mp/src/stores/persona/memory.ts)）

- 事实记忆 `MemoryFact`：`importance × 0.5^(days / 30)`，半衰期 30 天，低于 `FACT_MIN_STRENGTH=0.5` 被遗忘。
- 反馈记忆 `FeedbackSample`：`count × 0.5^(days / 7)`，半衰期 7 天。
- 相关性检索 `findRelevantFacts`：bigram Jaccard 相似度（内容 + 关键词拼接）结合记忆强度，取 topK。
- 每次对话：AI 优先抽取 `memoryUpdates`（facts / 滚动 summary / behavior），缺失时回退旧正则规则；`addMemoryFact` 命中已存在事实时提升重要度。

### 5.3 AI 服务接入（三种模式，互不冲突）

1. **客户端直连（默认）**：设置 → AI 服务 → 添加模型（名称 / 模型 ID / 接口地址 / API Key）。支持 DeepSeek、OpenAI（gpt-*/o1-*/o3-*）、Moonshot（kimi）、智谱（glm-*），`resolveProvider` 按模型名前缀路由。
   - 注意：`deepseek-reasoner` 与 `o1-*`/`o3-*` 为**推理慢模型**，`isReasoningModel` 会将其自动排到 failover 链末尾（快速模型优先）。
   - 推理模型不支持 `response_format` 强制 JSON，`supportsJsonMode` 返回 false，降级为提示词约束 + 客户端容错解析。
2. **uniCloud 网关兜底**：设置 → 云端网关兜底开关。客户端直连全部失败后自动请求一次网关。
   - 内置常量 `BUILTIN_GATEWAY_URL / BUILTIN_GATEWAY_TOKEN`（[models.ts](file:///workspace/complement-digital-human-mp/src/pages/chat-conversation/modules/models.ts#L19-L20)）可填入开发者自部署网关，用户无需配置 API Key 即可使用内置模型；也可由用户在设置页填自定义地址与令牌。
   - 兼容旧数据：`LEGACY_API_KEY_KEY='deepseek_api_key'` 旧版单 Key 自动迁移为一条 DeepSeek 模型。
3. **无 AI 可用时**：自动使用 `mock.ts` 的五场景演示回复（decision/emotion/relationship/goal/perspective/default），保证测评后即可完整体验。

## 9. 已知遗留问题与改进建议

1. **网关限流为进程内存态**：云函数冷启动即重置，防刷需替换为 Redis / 数据库计数，或依赖平台层限流。
2. **网关未开启流式**：`chat-gateway/index.js` 上游请求 `stream: false`（客户端直连才走流式）。若要网关也流式，需改造 `requestUpstream` 以 `res.on('data')` 透传分块到客户端。
3. **API Key 导出**：备份导出包含 `ai_models`（含用户填写的 API Key），换机导入时方便，但隐私上存在泄露风险；可考虑导出时置空 apiKey、导入时保留本机旧值。
4. **对话历史截断**：`buildHistory()` 只取最近 7 条消息、无 token 预算估算；长对话上下文会膨胀，建议接入历史摘要或按 token 裁剪。
5. **测评题库规模**：MBTI 16 题、大五 30 题为自研轻量版本，置信度算法（`intensity × consistency`）未经过大规模信效度验证；产品上线若需严肃性，建议换用标准量表并做常模校准。
6. **N 维度语义**：大五中 N 分越高代表情绪稳定性越低，但 UI 文案与部分描述可能被误读（"细腻敏感" 对应高 N），需统一话术。
7. **内置网关常量留空**：`BUILTIN_GATEWAY_URL / BUILTIN_GATEWAY_TOKEN` 默认为空，正式分发前需填入已部署网关，否则用户必须自行配置 API Key。
8. **`使用指南.md` 需同步**：其中 `stores/persona.ts` 路径描述已过时（现为 `stores/persona/` 目录），建议下次改版时更新。
